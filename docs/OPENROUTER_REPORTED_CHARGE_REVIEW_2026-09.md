# Response-reported OpenRouter charges

Status: isolated full gate and exact Vercel production verification passed; cloud CI `34373798730` remains in progress.

## Defect and scope

The production client normalized reasoning correctly after `640d584`, but still discarded `usage.cost` and recomputed every charge from the configured model rate. This misreported discounted, higher-priced and free calls, could not account for a returned model without a configured rate, and conflated a BYOK router fee with its separate upstream bill. The initial 25-case regression failed 22 cases before this patch (`/tmp/ysa-openrouter-reported-cost-before.log`). No paid request was made to reproduce it.

The existing transport now validates the response charge and feeds it to the existing shared accountant. Credit-funded responses count `usage.cost` once; their upstream breakdown is not added again. BYOK responses count the known router fee plus the reported external inference cost. Missing or malformed parts retain independently known charges and an incomplete-accounting flag. Invalid charges do not silently become configured-rate prices. Zero is a valid reported charge; missing charge fields in older responses retain the former configured-rate compatibility path, not a claim of exact billing evidence.

The [official usage contract](https://openrouter.ai/docs/cookbook/administration/usage-accounting) documents response costs and upstream details without an extra accounting request. [BYOK documentation](https://openrouter.ai/docs/guides/overview/auth/byok) separates OpenRouter fees from the provider's inference bill. [OpenRouter support](https://openrouter.ai/support) identifies credits as USD-denominated. The patch does not amortize credit-purchase fees or claim to reconcile invoices. Current credit-funded retained chat responses include a positive upstream breakdown; documentation about generation-statistics fields is not incorrectly applied to those completion responses.

No prompts, request bodies, output ceilings, model routes, provider preferences, retry settings, module paid flags or historical receipts change. Native Gemini and other providers keep their existing token-rate semantics. The serialized usage-summary shape is unchanged. No extra HTTP request, price lookup or deployment endpoint is introduced.
